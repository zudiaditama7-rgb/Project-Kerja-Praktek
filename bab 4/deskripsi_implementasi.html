4.11 Implementasi

Gambar 4. 68 Tampilan Login Semua User
Halaman ini merupakan antarmuka awal yang digunakan oleh seluruh aktor (Admin, Kepala Sekolah, Wali Kelas, Guru Mapel, dan Guru Pengganti) untuk masuk ke dalam sistem. Pengguna diwajibkan memasukkan username dan password yang valid. Sistem akan secara otomatis mengidentifikasi hak akses atau peran pengguna berdasarkan data autentikasi yang dimasukkan, lalu mengarahkannya ke halaman dashboard yang sesuai dengan perannya.
4.11.1 Implementasi Halaman Admin
Gambar 4. 69 Tampilan Dashboard Admin
Halaman dashboard admin menampilkan ringkasan informasi statistik secara keseluruhan, seperti total siswa aktif, total wali kelas, dan grafik kehadiran harian. Pada halaman ini juga terdapat pembaruan data presensi terbaru secara real-time, memberikan admin pandangan umum mengenai kondisi operasional presensi di madrasah pada hari tersebut.
Gambar 4. 70 Tampilan Fitur Data Semua Siswa
Antarmuka ini digunakan oleh admin untuk mengelola data induk siswa. Admin dapat melihat daftar seluruh siswa beserta kelas dan tahun ajarannya. Melalui halaman ini, admin memiliki hak akses penuh untuk menambah data siswa baru, mengedit informasi siswa yang ada, serta menghapus data siswa jika diperlukan.
Gambar 4. 71 Tampilan Fitur Riwayat Akademik Semua Siswa
Halaman ini secara khusus menampilkan rekam jejak akademik setiap siswa dari waktu ke waktu. Admin dapat melacak perkembangan kelas siswa mulai dari kelas awal hingga kelas akhir, memastikan bahwa data kenaikan kelas atau rotasi kelas tercatat dengan akurat dalam riwayat historis sistem.
Gambar 4. 72 Tampilan Fitur Managemen User Oleh Admin
Fitur ini merupakan pusat pengaturan hak akses pengguna sistem. Admin bertugas menambahkan akun guru atau staf, mengatur kata sandi, serta menetapkan peran (role) kepada setiap pengguna. Halaman ini juga dirancang untuk mendukung multi-peran, sehingga admin dapat memberikan lebih dari satu jabatan (misalnya sebagai Wali Kelas sekaligus Guru Mapel) pada satu pengguna.
Gambar 4. 73 Tampilan Fitur Manajemen Tahun Ajaran Oleh Admin
Halaman manajemen tahun ajaran digunakan untuk mengatur periode semester aktif di sekolah. Admin dapat membuat tahun ajaran baru, menentukan tanggal mulai dan selesai untuk semester ganjil dan genap, serta mengaktifkan semester berjalan. Pengaturan ini sangat krusial karena seluruh pencatatan presensi akan dikaitkan dengan tahun ajaran yang sedang aktif.
Gambar 4. 74 Tampilan Fitur Manajemen Kelas dan Wali Kelas
Antarmuka ini berfungsi untuk mendistribusikan siswa ke dalam rombongan belajar (rombel) atau kelas. Di halaman ini, admin juga bertanggung jawab untuk menugaskan seorang guru agar menjadi Wali Kelas pada kelas tertentu. Sistem akan memastikan hanya ada satu wali kelas yang aktif memegang satu kelas pada satu periode semester.
Gambar 4. 75 Tampilan Fitur Laporan Presensi
Halaman ini menyediakan fitur penyaringan (filter) data absensi tingkat lanjut. Admin dapat menarik laporan kehadiran seluruh siswa madrasah dengan parameter waktu, rentang tanggal, atau kelas tertentu, yang nantinya digunakan sebagai bahan rekapitulasi atau arsip sekolah.
Gambar 4. 76 Tampilan Kelola Penugasan Guru Pengganti Oleh Admin
Halaman ini menampilkan daftar pengajuan tugas atau izin dari guru (Wali Kelas/Guru Mapel) yang berhalangan hadir. Admin bertugas meninjau alasan ketidakhadiran, melihat dokumen lampiran tugas, dan menentukan guru piket atau guru pengganti yang akan ditugaskan untuk mengisi kelas yang kosong tersebut.
4.11.2 Implementasi Halaman Wali Kelas
Gambar 4. 77 Tampilan Dashboard Wali Kelas
Halaman beranda untuk Wali Kelas didesain untuk menampilkan visualisasi cepat mengenai kondisi anak perwaliannya. Terdapat grafik kehadiran harian, kalender akademik, dan persentase kehadiran spesifik untuk kelas yang diampu, sehingga wali kelas dapat dengan mudah memantau tingkat kedisiplinan siswanya.
Gambar 4. 78 Tampilan Input Presensi Oleh Wali Kelas
Halaman ini digunakan oleh Wali Kelas untuk mencatat daftar hadir harian siswanya. Pengguna dapat memilih status kehadiran (Hadir, Izin, Sakit, Alpha) untuk setiap siswa. Sistem juga menyediakan kolom untuk mengunggah dokumen bukti jika siswa berstatus sakit atau izin, memastikan data presensi terekam valid.
Gambar 4. 79 Tampilan Scan QR Input Presensi Siswa
Sebagai alternatif dari input manual, halaman ini memanfaatkan kamera perangkat (HP atau Laptop) untuk membaca kartu QR Code milik siswa. Saat QR Code berhasil dipindai, sistem akan secara instan mencatat siswa tersebut hadir, sehingga proses presensi di pagi hari menjadi jauh lebih cepat dan efisien.
Gambar 4. 80 Tampilan Fitur Pengajuan Rekap Presensi Oleh Wali Kelas
Pada akhir periode (bulanan atau semester), Wali Kelas menggunakan halaman ini untuk menyusun rekapitulasi kehadiran kelasnya. Rekap ini kemudian diajukan ke dalam sistem untuk meminta persetujuan secara digital (approval) dari Kepala Sekolah sebelum dicetak sebagai laporan resmi.
Gambar 4. 81 Tampilan Hasil Rekap Presensi Berbentuk File Pdf yang Sudah di Acc Sama Kepala Sekolah
Halaman ini menunjukkan hasil akhir berupa dokumen PDF rekap presensi yang telah diverifikasi dan disetujui (di-acc) oleh Kepala Sekolah. Dokumen PDF ini sudah di-generate secara rapi oleh sistem dengan format standar sekolah dan siap untuk dicetak atau dibagikan saat pembagian rapor.
Gambar 4. 82 Tampilan Fitur Pengajuan Guru Pengganti Oleh Wali Kelas
Bila Wali Kelas berhalangan hadir, mereka menggunakan halaman ini untuk mengirimkan permohonan izin kepada sistem. Mereka diwajibkan menyertakan alasan, surat keterangan (jika sakit), dan mengunggah lembar tugas atau materi pelajaran yang harus dikerjakan oleh siswa selama mereka tidak berada di kelas.
4.11.3 Implementasi Halaman Kepala Sekolah
Gambar 4. 83 Tampilan Dashboard Kepala Sekolah
Dashboard Kepala Sekolah memberikan sajian data tingkat tinggi (high-level) terkait seluruh aktivitas presensi di madrasah. Halaman ini memfokuskan pada pengawasan makro, menampilkan grafik ringkasan kehadiran seluruh kelas, serta notifikasi cepat bila ada pengajuan rekap yang memerlukan tindak lanjut persetujuan.
Gambar 4. 84 Tampilan Fitur Monitoring Presensi Siswa
Melalui fitur ini, Kepala Sekolah dapat melakukan inspeksi atau pemantauan secara langsung (real-time) terhadap kedisiplinan siswa di kelas mana pun. Kepala sekolah dapat memfilter berdasarkan tanggal atau kelas tertentu untuk memantau tren kehadiran tanpa perlu menunggu laporan manual dari guru.
Gambar 4. 85 Tampilan Fitur Persetujuan Rekap Presensi
Halaman ini adalah daftar tunggu persetujuan (approval) atas rekapitulasi kehadiran yang diajukan oleh para Wali Kelas setiap bulannya. Kepala Sekolah dapat meninjau hasil rekap tersebut, dan jika data sudah sesuai, memberikan klik persetujuan (ACC) sehingga rekap tersebut disahkan secara sistem.
Gambar 4. 86 Tampilan Fitur Laporan Semua Presensi
Halaman ini menyajikan laporan komprehensif seluruh data kehadiran sekolah. Kepala Sekolah dapat melihat rincian arsip data historis, mencari catatan ketidakhadiran siswa tertentu, dan mengekspor data yang ada sebagai bentuk laporan manajerial atau pertanggungjawaban.
4.11.4 Implementasi Halaman Guru Pengganti
Gambar 4. 87 Tampilan Dashboard Guru Pengganti
Halaman dashboard untuk Guru Pengganti difokuskan pada penugasan yang diberikan kepada mereka hari itu. Di layar ini, mereka dapat melihat kelas mana yang harus mereka isi atau gantikan, lengkap dengan status jam mengajar dan deskripsi instruksi yang ditinggalkan oleh guru aslinya.
Gambar 4. 88 Tampilan Input Presensi Oleh Guru Pengganti
Sama halnya dengan fitur pada guru utama, halaman ini memberikan wewenang kepada guru pengganti/piket untuk mengisi absensi harian pada kelas yang sedang dititipkan kepadanya. Hal ini memastikan bahwa pencatatan kehadiran siswa tidak terputus meskipun wali kelas atau guru mapel aslinya sedang berhalangan.
Gambar 4. 89 Tampilan Riwayat Presensi
Halaman ini memungkinkan Guru Pengganti untuk melihat rekam jejak atau log presensi yang telah mereka input sebelumnya. Tujuannya adalah sebagai verifikasi pribadi bahwa tugas presensi yang mereka wakilkan telah sukses tersimpan di pangkalan data sistem.
4.11.5 Implementasi Halaman Guru Mapel
Gambar 4. 90 Tampilan Dashboard Guru Mapel
Dashboard Guru Mata Pelajaran (Mapel) didesain sangat spesifik dengan menampilkan kotak-kotak jadwal kelas yang diampunya saja. Hal ini memberikan antarmuka yang bersih dan memudahkan guru untuk langsung memilih ruang kelas virtual sebelum mereka mulai mengajar dan mengabsen siswanya.
Gambar 4. 91 Tampilan Pilih Kelas Sebelum Input Presensi Oleh Guru Mapel
Sebelum memasuki mode input absensi, halaman ini bertindak sebagai pintu gerbang. Guru Mapel diwajibkan untuk mengonfirmasi dan memilih dengan tepat kelas mana yang akan diabsen pada jam tersebut, mencegah terjadinya salah catat kehadiran ke kelas yang berbeda.
Gambar 4. 92 Tampilan Pengajuan Guru Pengganti Oleh Guru Mapel
Serupa dengan prosedur Wali Kelas, halaman ini digunakan oleh Guru Mapel ketika mereka berhalangan mengajar pada jam mata pelajarannya. Mereka dapat menitipkan materi atau Lembar Kerja Siswa (LKS) melalui form ini agar kegiatan belajar mengajar (KBM) pada jam tersebut tetap berlangsung dengan baik.
