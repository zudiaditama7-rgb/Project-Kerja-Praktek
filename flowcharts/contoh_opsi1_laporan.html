3.x.x Skenario Use Case Sistem

Berdasarkan rancangan Use Case Diagram yang telah diuraikan, interaksi aktor dengan sistem dibagi menjadi dua kategori, yaitu Use Case Pendukung (bersifat standar administratif) dan Use Case Utama (bersifat inti dari logika bisnis sistem presensi).

A. Deskripsi Use Case Pendukung (Ringkasan)

Use case pendukung meliputi aktivitas dasar yang dilakukan oleh hampir seluruh aktor (Admin, Wali Kelas, Guru Mapel, Guru Pengganti, dan Kepala Sekolah) dalam menggunakan sistem. Rangkuman aktivitas tersebut dapat dilihat pada Tabel 1 di bawah ini:

Tabel 1. Rangkuman Use Case Pendukung (Standar Sistem)
No Nama Use Case Aktor Terlibat Deskripsi Singkat
1 Melakukan Login Semua Aktor Proses autentikasi dengan memasukkan username dan password untuk memvalidasi hak akses masuk ke dalam sistem.
2 Melihat Dashboard Semua Aktor Menampilkan halaman utama yang berisi ringkasan data dan notifikasi sesuai dengan otorisasi masing-masing peran.
3 Mengelola Profil Semua Aktor Fasilitas bagi pengguna untuk memperbarui data pribadi dan mengubah kata sandi akun mereka demi keamanan.
4 Melihat Riwayat Presensi Wali Kelas, Guru Pengganti Fasilitas untuk memantau log atau catatan riwayat kehadiran yang sudah pernah diinput sebelumnya.
5 Melihat Data Siswa Kelas Wali Kelas, Guru Mapel, Guru Pengganti Melihat daftar identitas detail dari siswa-siswa yang berada di bawah pengawasan atau kelas pengajaran aktor tersebut.
6 Melakukan Logout Semua Aktor Proses mengakhiri sesi aktif secara aman dan keluar dari aplikasi.

B. Deskripsi Use Case Utama (Detail)

Use case utama merupakan interaksi spesifik yang mewakili fitur inti dari Sistem Informasi Presensi Siswa. Berikut adalah penjabaran detail arus kerja dari proses-proses utama tersebut:

Tabel 2. Deskripsi Use Case Input Presensi Harian (Wali Kelas)
Nama use case Input Presensi Harian
Kebutuhan Wali Kelas dapat mencatat daftar kehadiran siswa di kelasnya setiap hari
Tujuan Merekam data presensi (kehadiran, sakit, izin, alpa) ke dalam sistem
Prekondisi Wali Kelas sudah berada di menu Presensi dan memilih jadwal
Kondisi Gagal Gagal menyimpan data presensi ke dalam database
Aktor Utama Wali Kelas
Arus Utama 1. Wali kelas membuka form/menu Input Presensi Harian
2. Menentukan metode input (melalui Scan atau Manual)
3. Menyelesaikan proses pencatatan
4. Sistem menyimpan data kehadiran ke database
Post Kondisi Data presensi harian siswa berhasil direkam dan berstatus tersimpan
Tabel 3. Deskripsi Use Case Presensi via QR Code (Scan)
Nama use case Presensi via QR Code (Scan)
Kebutuhan Guru/Wali Kelas dapat memindai QR Code siswa menggunakan kamera untuk presensi
Tujuan Mempercepat proses pencatatan presensi menggunakan pemindai QR secara otomatis
Prekondisi Kamera perangkat aktif dan berada di form presensi
Kondisi Gagal QR Code rusak/tidak terbaca, kamera error, atau QR Code tidak valid
Aktor Utama Wali Kelas / Guru Mapel / Guru Pengganti
Arus Utama 1. Guru memilih opsi "Scan QR"
2. Mengarahkan kamera pemindai ke kartu QR Code milik siswa
3. Sistem mendeteksi dan memvalidasi identitas siswa dari QR
4. Sistem mencatat siswa tersebut hadir
Post Kondisi Kehadiran siswa tercatat otomatis berdasarkan scan QR Code
Tabel 4. Deskripsi Use Case Approval Laporan Rekap (Kepala Sekolah)
Nama use case Approval Laporan Rekap
Kebutuhan Kepala Sekolah memeriksa dan menyetujui laporan presensi bulanan
Tujuan Sebagai legalisasi bahwa laporan absensi bulan tersebut sah dan valid
Prekondisi Ada laporan berstatus "Menunggu Persetujuan" dari wali kelas
Kondisi Gagal Gagal memuat dokumen laporan atau gagal mengubah status di database
Aktor Utama Kepala Sekolah
Arus Utama 1. Kepala Sekolah membuka notifikasi pengajuan Approval Laporan
2. Memeriksa ringkasan dan detail laporan absensi bulanan tersebut
3. Memutuskan untuk menyetujui (Approve) atau menolak (Reject) laporan
Post Kondisi Laporan rekapitulasi berpindah status dari proses peninjauan
