Daftar Lengkap Sequence Diagram Sistem

Kumpulan Sequence Diagram untuk seluruh aktor dan proses bisnis pada Sistem Presensi Madrasah.

Gambar 4.1 Sequence Diagram Melakukan Login (Semua User)
sequenceDiagram autonumber actor Pengguna participant ViewLogin as Halaman Login participant Controller as AuthController participant Database as Database (users) Pengguna->>ViewLogin: 1. Input Username & Password ViewLogin->>Controller: 2. Submit Data Kredensial Controller->>Database: 3. Query Cek Kredensial (Username) Database-->>Controller: 4. Kembalikan Data User (Hash) alt Kredensial Valid Controller->>Controller: 5. Verifikasi Hash Password (Sesuai) Controller->>Controller: 6. Set Session Login & Role Controller-->>ViewLogin: 7. Redirect ke Dashboard sesuai Role ViewLogin-->>Pengguna: 8. Tampilkan Dashboard else Kredensial Tidak Valid Controller->>Controller: 5. Verifikasi Hash Password (Gagal) Controller-->>ViewLogin: 6. Redirect Back dengan Error ViewLogin-->>Pengguna: 7. Tampilkan Pesan "Login Gagal" end
Deskripsi: Diagram mewakili proses autentikasi untuk semua peran (Admin, Wali Kelas, Guru Mapel, Guru Pengganti, Kepala Sekolah). Sistem memvalidasi kredensial dan mengarahkan pengguna ke dashboard berdasarkan hak akses (Role).
Gambar 4.2 Sequence Diagram Admin Mengelola Data Siswa (CRUD)
sequenceDiagram autonumber actor Admin participant View as Modul Data Siswa participant Controller as SiswaController participant Database as Database (siswa) Admin->>View: 1. Buka Form Tambah/Edit Data Siswa Admin->>View: 2. Isi Data (NIS, Nama, Kelas, dll) Admin->>View: 3. Klik "Simpan" View->>Controller: 4. Request POST Data Siswa Controller->>Controller: 5. Validasi Input (NIS Unik, Required) alt Validasi Sukses Controller->>Database: 6. Query Insert / Update Data Database-->>Controller: 7. Return Sukses Controller-->>View: 8. Redirect ke Tabel Master View-->>Admin: 9. Tampilkan "Data Berhasil Disimpan" else Validasi Gagal (Misal NIS Kembar) Controller-->>View: 6. Redirect Back with Errors View-->>Admin: 7. Tampilkan Peringatan "NIS Sudah Digunakan" end
Deskripsi: Perwakilan dari alur CRUD (Create, Read, Update, Delete). Alur ini mirip dengan modul pengelolaan master data lainnya seperti kelola Kelas, kelola User, atau kelola Tahun Ajaran.
Gambar 4.3 Sequence Diagram Admin Mencetak Kartu QR Siswa
sequenceDiagram autonumber actor Admin participant View as Data Siswa participant Controller as CetakQRController participant PDFEngine as Library PDF/QR participant Database as Database (siswa) Admin->>View: 1. Pilih Kelas / Centang Nama Siswa Admin->>View: 2. Klik "Cetak Kartu QR" View->>Controller: 3. Request Cetak Berdasarkan ID Controller->>Database: 4. Ambil Data Siswa (NIS, Nama, Foto) Database-->>Controller: 5. Kembalikan Data Siswa Controller->>PDFEngine: 6. Generate QR Code dari NIS Controller->>PDFEngine: 7. Render Template HTML ke PDF PDFEngine-->>Controller: 8. File PDF Siap Controller-->>View: 9. Stream/Download File PDF View-->>Admin: 10. File PDF ID Card Terunduh
Deskripsi: Admin melakukan generate ID Card yang dilengkapi dengan QR Code. QR Code dihasilkan secara dinamis berdasarkan Nomor Induk Siswa (NIS) untuk keperluan scan presensi harian.
Gambar 4.4 Sequence Diagram Presensi Harian via Scan QR Code
sequenceDiagram autonumber actor Guru as Wali / Guru Mapel participant View as Halaman Scan QR participant Controller as PresensiController participant DB_Siswa as Database (siswa) participant DB_Presensi as Database (presensi) Guru->>View: 1. Buka Kamera Scanner QR Guru->>View: 2. Arahkan Kartu QR Siswa ke Kamera View->>Controller: 3. Kirim Data NIS dari QR (AJAX) Controller->>DB_Siswa: 4. Cek Validitas NIS Siswa alt Siswa Ditemukan DB_Siswa-->>Controller: 5. Kembalikan Data Siswa Controller->>DB_Presensi: 6. Cek Status Presensi Hari Ini alt Belum Presensi DB_Presensi-->>Controller: 7. Status Kosong Controller->>DB_Presensi: 8. Insert Presensi (Status: Hadir) Controller-->>View: 9. Response Success (Bawa Data Profil) View-->>Guru: 10. Tampilkan Notif "Presensi NIS... Berhasil" else Sudah Presensi DB_Presensi-->>Controller: 7. Status Sudah Ada Controller-->>View: 8. Response Warning View-->>Guru: 9. Tampilkan Notif "Siswa Sudah Terabsen" end else Siswa Tidak Ditemukan DB_Siswa-->>Controller: 5. Data Null Controller-->>View: 6. Response Error View-->>Guru: 7. Tampilkan Notif "QR Code Tidak Valid" end
Deskripsi: Alur utama pencatatan kehadiran menggunakan kamera device guru untuk men-scan QR Code siswa. Sistem memvalidasi agar tidak terjadi absen ganda di hari yang sama.
Gambar 4.5 Sequence Diagram Input Presensi Manual (Sakit/Izin/Alpa)
sequenceDiagram autonumber actor Guru as Wali / Guru Mapel participant View as Tabel Presensi Manual participant Controller as PresensiController participant Database as Database (presensi) Guru->>View: 1. Buka Menu Presensi Manual Kelas View->>Controller: 2. Request Data Siswa & Status Hari Ini Controller->>Database: 3. Fetch Data Siswa + Presensi Database-->>Controller: 4. Return Data Controller-->>View: 5. Tampilkan Tabel Daftar Siswa Guru->>View: 6. Pilih Status (Sakit/Izin/Alpa) pd Siswa Tertentu Guru->>View: 7. Klik "Simpan Presensi" View->>Controller: 8. Deskripsi: Digunakan apabila scanner QR tidak berfungsi, siswa lupa membawa kartu, atau guru harus menginputkan keterangan Sakit, Izin, atau Alpa secara manual melalui tabel daftar siswa.
Gambar 4.6 Sequence Diagram Pengajuan Tugas Pengganti (Oleh Guru)
sequenceDiagram autonumber actor Guru as Guru (Berhalangan) participant View as Form Pengajuan participant Controller as TugasController participant Database as Database (tugas_pengganti) Guru->>View: 1. Validasi File Modul/Surat alt Validasi Berhasil Controller->>Database: 5. Insert Data (Status: Pending) Database-->>Controller: 6. Data Tersimpan Controller-->>View: 7. Tampilkan Pesan Error Validasi end
Deskripsi: Alur yang dilakukan guru ketika berhalangan hadir. Guru mengisi form pengajuan agar kelasnya dicarikan guru pengganti, beserta mengunggah file materi/modul pembelajaran sementara.
Gambar 4.7 Sequence Diagram Admin Menugaskan Guru Pengganti
sequenceDiagram autonumber actor Admin participant View as Panel Approval participant Controller as AdminTugasController participant Database as Database (tugas_pengganti) Admin->>View: 1. Buka Notifikasi Pengajuan Masuk View->>Controller: 2. Request Detail Pengajuan Controller->>Database: 3. Ambil Data Tugas & Modul Database-->>Controller: 4. Kembalikan Data Controller-->>View: 5.
