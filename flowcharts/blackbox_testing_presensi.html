Lampiran: Pengujian Sistem (Blackbox Testing)

Sistem Informasi Presensi Siswa

Tabel berikut menyajikan skenario pengujian fungsional sistem menggunakan metode Blackbox Testing (pendekatan Equivalence Partitioning). Pengujian ini dilakukan untuk memvalidasi bahwa seluruh fitur yang tersedia untuk aktor Admin, Guru Mapel, Guru Pengganti, Wali Kelas, dan Kepala Sekolah berjalan dengan baik dan mampu menangani kesalahan input (*error handling*).

1. Pengujian Modul Autentikasi (Semua Aktor)

No Fungsi yang Diuji Skenario Input Hasil yang Diharapkan (*Expected Result*) Hasil Pengujian Kesimpulan
1.1 Login Sukses Memasukkan Username dan Password yang valid sesuai hak akses yang terdaftar. Sistem memberikan akses masuk dan mengarahkan ke halaman Dashboard yang sesuai dengan peran (role) pengguna. Sesuai Valid
1.2 Login Gagal (Password Salah) Memasukkan Username yang benar tetapi Password salah. Sistem menolak akses, tetap di halaman Login, dan menampilkan notifikasi "Kredensial tidak cocok / Password salah". Sesuai Valid
1.3 Validasi Form Kosong Mengeklik tombol "Login" dalam keadaan kolom Username dan Password kosong. Sistem mencegah pengiriman form dan memunculkan peringatan "Please fill out this field." di sekitar kotak input. Sesuai Valid
1.4 Fungsi Logout Mengeklik tombol "Logout" dari dalam sistem. Sesi (session) pengguna dihancurkan, dan pengguna dikembalikan ke halaman Login awal. Sesuai Valid

2. Pengujian Modul Aktor: Admin

Fokus: Pengelolaan data master (Siswa, Kelas, Guru, Jadwal).

No Fungsi yang Diuji Skenario Input Hasil yang Diharapkan (*Expected Result*) Hasil Pengujian Kesimpulan
2.1 Tambah Data Siswa Baru Mengisi form data siswa lengkap (NIS, Nama, Kelas) dengan data valid lalu klik "Simpan". Data tersimpan di database dan muncul di tabel siswa. Tampil pesan "Siswa berhasil ditambahkan". Sesuai Valid
2.2 Validasi Duplikasi NIS Siswa Memasukkan data siswa baru menggunakan NIS yang sudah pernah didaftarkan pada siswa lain. Sistem menolak penyimpanan, data tidak masuk tabel, dan muncul peringatan "NIS sudah terdaftar". Sesuai Valid
2.3 Persetujuan Tugas Pengganti Mengeklik tombol "Setujui" (Assign) atau "Tolak" (Reject) pada usulan tugas pengganti dari Guru Mapel. Status tugas pengganti berubah di database dan notifikasi diteruskan ke Guru Mapel terkait secara langsung. Sesuai Valid
2.4 Hapus Data Guru Mengeklik tombol "Hapus" pada salah satu data guru di halaman kelola guru. Muncul dialog konfirmasi (Are you sure?). Jika disetujui, data guru hilang dari tabel kelola. Sesuai Valid

3. Pengujian Modul Aktor: Guru Mapel

Fokus: Input absensi kehadiran harian dan pembuatan QR Code penugasan.

No Fungsi yang Diuji Skenario Input Hasil yang Diharapkan (*Expected Result*) Hasil Pengujian Kesimpulan
3.1 Input Presensi Harian Mengubah status absensi siswa di kelas yang diajar (Hadir, Izin, Sakit, Alpa), lalu klik "Simpan Presensi". Data presensi berhasil disimpan. Status kehadiran siswa tercatat dan masuk ke rekap absensi kelas. Sesuai Valid
3.2 Pembuatan Tugas Pengganti (Generate QR) Mengajukan usulan ketidakhadiran (tugas pengganti) untuk jadwal mengajar tertentu. Sistem berhasil merekam usulan dan membuat (generate) sebuah QR Code khusus untuk jadwal tersebut. Sesuai Valid
3.3 Lihat Riwayat Mengajar Membuka halaman riwayat atau laporan absensi yang sudah di-input sebelumnya. Sistem menampilkan tabel rekaman tanggal dan jumlah siswa yang Hadir/Izin/Sakit pada sesi tersebut. Sesuai Valid

4. Pengujian Modul Aktor: Guru Pengganti

Fokus: Serah terima tugas via scanner QR Code dan pengisian presensi.

No Fungsi yang Diuji Skenario Input Hasil yang Diharapkan (*Expected Result*) Hasil Pengujian Kesimpulan
4.1 Scan QR Code (Valid) Menggunakan fitur Scanner untuk memindai QR Code tugas pengganti yang benar dan masih aktif. QR berhasil dipindai. Sistem mengalihkan kewenangan kelas kepada Guru Pengganti untuk mengisi presensi. Sesuai Valid
4.2 Scan QR Code (Tidak Valid/Expired) Memindai QR Code yang usianya sudah kadaluarsa (di luar tanggal jadwal) atau QR palsu. Sistem menolak pendelegasian, muncul peringatan "QR Code tidak valid atau sudah kadaluarsa". Sesuai Valid
4.3 Input Presensi (Delegasi) Menyimpan presensi siswa (Hadir/Izin/Sakit) setelah berhasil melakukan scan QR. Presensi siswa tercatat secara sah di database atas nama Guru Mapel asli, dikerjakan oleh Guru Pengganti. Sesuai Valid

5. Pengujian Modul Aktor: Wali Kelas

Fokus: Pemantauan rekapan absensi siswa khusus pada kelas perwaliannya.

No Fungsi yang Diuji Skenario Input Hasil yang Diharapkan (*Expected Result*) Hasil Pengujian Kesimpulan
5.1 Akses Rekapitulasi Kelas Mengakses halaman Laporan/Rekapitulasi Absensi dari Dashboard Wali Kelas. Sistem hanya menampilkan data absensi siswa yang tergabung di dalam kelas yang dibina oleh Wali Kelas tersebut. Sesuai Valid
5.2 Filter Periode Laporan Menentukan rentang tanggal laporan (misal: 1 Juli - 31 Juli) dan mengeklik "Tampilkan". Tabel rekapitulasi memperbarui akumulasi jumlah Hadir, Sakit, Izin, dan Alpa sesuai rentang tanggal. Sesuai Valid
5.3 Cetak Laporan Kelas (PDF) Mengeklik tombol "Cetak PDF" pada halaman rekapitulasi. Sistem mengunduh dokumen PDF berisi tabel rekap absensi yang rapi dan siap cetak untuk diserahkan ke siswa/wali murid. Sesuai Valid

6. Pengujian Modul Aktor: Kepala Sekolah

Fokus: Pemantauan secara makro atas seluruh tingkat kehadiran sekolah.

Kesimpulan Pengujian

Berdasarkan hasil pengujian yang telah dilakukan, Sistem Informasi Presensi Siswa berbasis Web ini telah berhasil memenuhi kebutuhan fungsional dan non-fungsional sesuai dengan perancangan awal. Seluruh fitur utama pada setiap tingkatan hak akses pengguna (role) telah diuji menggunakan metode Blackbox Testing dan menunjukkan hasil yang memuaskan.

Dari sisi operasional harian (Guru Mata Pelajaran dan Guru Pengganti), sistem mampu menjalankan proses pencatatan presensi siswa di kelas dengan akurat secara real-time. Penerapan inovasi pendelegasian kelas menggunakan Generate dan Scan QR Code terbukti mempermudah serah terima jam pelajaran kepada Guru Pengganti ketika Guru Utama berhalangan hadir, meminimalisir kekosongan kelas. Antarmuka yang dirancang sederhana dan responsif juga dinilai sangat memudahkan guru dalam menginput data di tengah kegiatan belajar mengajar.

Sementara dari sisi manajemen (Admin, Wali Kelas, dan Kepala Sekolah), sistem mampu memproses dan mengelola rekapitulasi data presensi siswa dengan sangat baik. Wali Kelas dapat dengan mudah memantau grafik tingkat kehadiran anak didiknya dan mencetak laporan (PDF). Kepala Sekolah juga dimudahkan dengan adanya Dashboard pemantauan global yang menyajikan persentase tingkat absensi seluruh sekolah sebagai bahan evaluasi. Fitur autentikasi dan validasi multi-level berjalan sesuai fungsinya, memastikan bahwa pengguna hanya bisa mengakses menu yang sesuai dengan porsinya.

Dari segi pengujian keamanan dan kinerja, sistem menunjukkan respons yang stabil meskipun data diakses oleh beberapa user pada waktu yang bersamaan. Pengujian validasi input menunjukkan bahwa database terlindungi dari masuknya data kosong atau duplikasi data (seperti NIS ganda), sehingga integritas data sekolah tetap terjaga.

Berdasarkan uji pengguna (User Acceptance Testing), para pengajar dan staf tata usaha memberikan tanggapan positif terhadap alur sistem yang jelas, kecepatan pembuatan rekap bulanan yang sebelumnya dilakukan secara manual, serta tampilan antarmuka yang rapi. Secara keseluruhan, sistem presensi ini telah berhasil diimplementasikan dengan baik dan layak untuk diterapkan secara penuh sebagai solusi digitalisasi akademik di lingkungan sekolah.

Saran Pengembangan Lanjutan

Meskipun sistem telah berjalan dengan baik, evaluasi menunjukkan bahwa sistem ini masih memiliki ruang untuk dikembangkan lebih lanjut guna memaksimalkan fungsinya. Beberapa saran untuk pengembangan sistem di masa mendatang antara lain:

  1. Integrasi Notifikasi Gateway: Mengembangkan fitur pengiriman pesan otomatis (misalnya melalui WhatsApp atau Email) kepada orang tua/wali murid secara real-time apabila anak mereka tercatat dengan status Alpa (Tanpa Keterangan) di sekolah.
  2. Pengembangan ke Platform Mobile (Android/iOS): Untuk ke depannya, sistem berbasis web ini dapat di-upgrade menjadi aplikasi mobile (Native/Hybrid) agar proses Scan QR Code oleh Guru Pengganti dan pemantauan oleh Kepala Sekolah bisa dilakukan lebih praktis melalui aplikasi khusus.
  3. Integrasi dengan Sistem E-Rapor: Membuka API (Application Programming Interface) agar hasil persentase kehadiran akhir semester yang direkap dari aplikasi presensi ini dapat langsung ditarik secara otomatis ke dalam sistem penilaian E-Rapor nasional sekolah.
